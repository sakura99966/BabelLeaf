## 2. 整改目标

0.4 PC 闭环只有在以下条件同时成立时才可通过：

1. 所有规划中的 PC 功能都由安装包内可到达的用户界面提供，不能只存在服务、类型、枚举、模拟器或单元测试。
2. EPUB、PDF、MOBI/AZW/AZW3、FB2、CBZ/ZIP/FBZ、TXT、Markdown、扫描页和图片目录使用真实合法样本通过有效、异常和恶意输入矩阵。
3. 文本翻译、双语阅读、字典、语音、OCR、漫画编辑、批处理和导出均通过精确候选安装包验证。
4. 原书保持逐字节不变；翻译、OCR、掩膜、校订和排版状态只进入无凭据的版本化 sidecar；导出只生成新文件。
5. 未经用户明确触发，不产生外部网络请求；显式翻译只能访问命名供应商的固定端点或回环 Ollama。
6. 性能、内存、磁盘、临时文件、并发、压缩解包和模型生命周期均受可执行预算约束。
7. 候选包具备可追溯源码、签名、哈希、SBOM、第三方声明、许可证检查和完整 CI 证据。

## 3. 不得改变的产品边界

- 不增加在线书库、网页抓取、账户、云同步、遥测、在线词典、云端 TTS 或自动后台翻译。
- 不上传整本书、页面图片、OCR 文本、字典内容或 sidecar。
- 不绕过或移除 DRM；DRM、加密和不支持文件必须给出明确诊断。
- 不把 API 密钥写入普通设置、日志、sidecar、备份、诊断、URL、导出文件或仓库。
- 不自动下载 OCR、修复或语音模型；模型必须由用户明确导入、校验、选择、卸载和移除。
- 不在基础安装包内引入通用 Python 运行时。OCR 和图像模型优先采用可替换、可移植、按需加载的本地运行时。
- 不为通过测试而放宽 CSP、固定供应商、资源上限、源文件不可变或许可证边界。

## 5. 实施前必须取得的外部输入

下列条件不是代码可以自行伪造的。缺少任一项时，可以继续开发和本地测试，但不能关闭相应验收项：

1. Windows 代码签名证书或受控签名服务，能够对最终 NSIS 候选包签名并验证时间戳和证书链。
2. DeepSeek、OpenAI、Anthropic 的非生产测试账户或合成测试密钥，通过受保护的本地/CI Secret 提供；不得写入仓库或测试制品。
3. 许可证允许测试和必要分发的 OCR 模型、真实格式样本、漫画/扫描页语料和字典样本；每个文件需要来源、许可证和 SHA-256。
4. 可重复的最低支持 Windows 主机或 VM 配置，包括 CPU、内存、磁盘、WebView2 和语音环境。
5. 中、英、日和竖排日文 OCR 的人工标注真值集，以及漫画导出视觉对比基准。
6. 若真实语音无法由自动化采集，需要批准的音频测试接收端或人工验收记录格式。

## 6. 检查点 R0：固化当前整改基线

### 目的

当前工作树包含大量已验证但未提交的整改，并且 `.git` 元数据在当前执行身份下不可写。继续开发会扩大无法追溯的变更集合。因此所有功能工作必须从基线固化开始。

### 实施步骤

1. 在正常用户权限下恢复 `.git` 和子模块 Git 元数据的可写能力，不改变源码内容。
2. 核对 `main`、`origin/main`、子模块固定提交和全部未跟踪文件；确认没有用户私有文件、`.env`、凭据、导入书籍或发布私钥进入 diff。
3. 对当前整改逐文件复审，并按以下逻辑拆分提交：
   - 依赖与安全；
   - Windows 测试启动器和 CI；
   - 双语阅读与翻译供应商校验；
   - 漫画编辑和资源限制；
   - 安装验证、性能工具和审计文档。
4. 子模块 `packages/tauri-plugins` 必须通过内容哈希确认后恢复为干净状态；不得提交纯行尾或状态缓存差异。
5. 建议从已审查基线创建 `codex/pc-0.4-acceptance-remediation`，推送远端备份后再开始后续实现。
6. 记录基线提交、树哈希、依赖锁哈希和当前安装包哈希。

### 通过条件

- 工作树干净；所有既有整改均有可审查提交；远端分支与本地一致。
- 不存在未说明的子模块、生成文件、凭据或用户数据变更。
- 远端基础 CI 对该基线全部通过。

## 7. 检查点 A：发布、安全和格式基础设施

### A1. 依赖、工具链和必需 CI

对应：BL-PC04-006、007、011、020。

1. 使用 Corepack 或仓库封装脚本强制本地、CI 和发布过程使用根 `packageManager` 指定的 pnpm 版本；任何版本不一致直接失败。
2. 保留并强制执行生产 npm 审计、Windows RustSec 审计、格式、TypeScript、Biome、Rust fmt、Clippy、单元、浏览器、Web E2E、Tauri 和原生 E2E。
3. RustSec 警告按 Windows、macOS、Android、iOS 和实际可达性分类。任何未来平台可达的 unsound 依赖必须在进入 0.5 前升级、移除或形成有期限的书面处置。
4. 将 vendored workspace 纳入 warning 审查；修复 FS 插件未使用变量，不以 `--no-deps` 隐藏。
5. 远端 `ci_gate` 必须依赖全部必需任务；跳过、取消和失败都不得被当作成功。
6. E2E 启动器对成功、失败、超时和中断都要回收端口、进程、WebView2 配置和临时目录。

### A2. 可执行格式与恶意输入矩阵

对应：BL-PC04-008。

1. 新增 `scripts/fixtures/generate-format-fixtures.*`，确定性生成不适合直接提交的恶意样本；合法可再分发样本存入 `apps/readest-app/test-data/formats/`。
2. 新增 `FORMAT_FIXTURE_MANIFEST.json`，至少记录：格式、语义、来源、许可证、生成器版本、SHA-256、期望诊断、最大处理时间、最大内存和清理要求。
3. 每种格式至少覆盖：有效、空、截断、结构错误、加密/DRM、超大、远程子资源、路径穿越和压缩膨胀；只对适用情形生成对应样本。
4. AZW/AZW3、Markdown、FBZ、图片目录和扫描 PDF 必须使用真实语义，禁止只重命名其他格式字节。
5. 测试必须经真实导入/解析入口执行，并断言：错误码、源文件 SHA 不变、无半成品 sidecar、无临时残留、资源上限生效。
6. 生成器输出置于受控临时目录，测试结束后只删除已验证的生成路径。

### A3. 本地优先网络捕获

对应：BL-PC04-010。

1. 新增 Windows 隔离网络测试脚本，在全新应用配置下记录 DNS、TCP 和 HTTP(S) 目标；证据绑定候选包 SHA。
2. 捕获场景至少包括：安装、首次启动、导入、阅读、搜索、本地字典、TTS、sidecar 重开、OCR、漫画导出、关闭、每个命名云供应商和回环 Ollama。
3. 普通本地场景的外部目标集合必须为空；显式翻译只允许固定供应商主机、端口和协议；Ollama 只允许配置的回环地址。
4. 使用本地受控端点验证 30x 跳转、跨主机跳转、凭据剥离、超时、证书失败和错误正文脱敏。
5. 对日志、URL、诊断、sidecar、崩溃输出和导出文件进行 API 密钥、原文片段和图像指纹扫描。
6. 生成机器可读白名单报告和原始网络证据；报告中只保留合成内容，不包含真实密钥或书籍。

### A4. 安装器、失败清理和来源绑定

对应：BL-PC04-005、018。

1. 建立单一发布命令：干净树检查 -> 标准 Tauri 配置构建 -> VersionInfo/标识校验 -> 精确字节安装验证 -> 签名 -> 最终哈希 -> 证据清单。
2. Smoke 配置产物只能进入独立测试目录，发布脚本必须拒绝 ProductName、identifier、配置摘要或文件名不匹配的文件。
3. 对安装器脚本增加故障注入：预检失败、安装失败、启动超时、卸载失败、进程占用、端口占用和脚本中断。
4. 每个故障场景都必须证明没有隔离 profile、安装目录、进程、端口、注册表、临时文件或合成凭据残留。
5. 增加从最后一个公开版本到候选版本的升级验证，并验证应用数据迁移与卸载保留策略。
6. 候选包不得先复制到 `release/` 再测试；只有通过全部门禁的同一字节才可原子提升为发布产物。

### A5. 供应链、许可证和对应源码

对应：BL-PC04-007、019、020。

1. 选择并固定 SPDX 或 CycloneDX 生成器版本，分别生成源码和二进制 SBOM。
2. 生成 npm、Cargo、子模块、模型、字体、字典、测试数据和外部工具的许可证清单及第三方声明。
3. 建立允许、人工审查和禁止许可证策略；未知许可证直接阻止发布。
4. 记录每个子模块 URL、固定提交、许可证和工作树状态。
5. 生成 AGPL 对应源码清单，确保发布二进制对应的源码提交、补丁、构建说明和 notices 可获得。
6. 最终安装包签名后再计算发布 SHA；验证签名、时间戳、证书链、产品名和版本。

## 8. 检查点 B：文本阅读与翻译 PC 闭环

### B1. 四种双语阅读模式和稳定锚点

对应：BL-PC04-004。

1. 明确 `original`、`translated`、`stacked`、`columns` 四种模式的渲染契约，统一进入真实 reader DOM，而不是仅存在于校订工作台。
2. 锚点以书籍内容身份、章节身份、规范化文本范围和上下文摘要组合建立，不依赖临时 DOM 索引或当前分页。
3. 翻译 sidecar 只保存原文指纹、锚点、译文、供应商、模型、提示版本、状态和人工校订；不得保存凭据。
4. 字体、字号、行高、页边距、窗口尺寸、书写方向和翻页模式变化后重新定位，不重写翻译记录。
5. 对锚点失配提供可见诊断和人工重新关联，不静默显示错误译文。
6. EPUB/TXT 必须完成安装包级 E2E；PDF、MOBI/AZW、FB2 在存在可选择文本时纳入同一矩阵。

### B2. 覆盖率和关键入口行为门禁

对应：BL-PC04-012。

1. 增加 `test:coverage`，采用渐进阈值：先固定不低于当前基线，再逐检查点提高；任何核心模块下降直接失败。
2. 对变更文件和核心模块设置比全局更严格的分支、函数和语句阈值。
3. 必须直接覆盖：
   - `TranslationWorkbenchDialog`、`TranslatorPopup`；
   - glossary、translation memory、review 面板；
   - `ComicWorkspaceDialog`、`ComicRegionEditor`；
   - `OcrModelPackPanel`、`OcrTextLayer`；
   - reader 双语模式和 sidecar 恢复。
4. 每个入口至少包含正常、取消、失败、持久化、重启和负向权限/资源场景。
5. 覆盖率报告绑定提交和测试命令，禁止只提高全局百分比而绕过未触达入口。

### B3. 性能基线和启动优化

对应：BL-PC04-013。

1. 正式定义冷启动、可交互、五分钟空闲、进程树工作集、Private Bytes、CPU、句柄、线程、磁盘和包体指标。
2. 每个场景至少多次运行并记录 p50/p95；证据包含主机、WebView2、候选包、fixture 和缓存状态。
3. 先分析进程树和前端 chunk，再决定优化：
   - 保留已实施的工作台/漫画工作区动态加载；
   - 将 OCR、PDF、压缩、字典和 TTS 依赖延迟到用户入口；
   - 停止启动期无关服务、插件注册和后台轮询；
   - 检查 Jieba/SimpleCC 重复资源，但只有全部 URL/worker 路径测试通过后才删除副本；
   - 对不可避免的 WebView2 基础开销单独记录，不从总用户可见工作集预算中隐去。
4. 当前 350 MiB 工作集预算保持有效，除非路线图经过明确批准修改；不得因失败自行放宽。
5. 正式最低主机五分钟测量通过前，BL-PC04-013 保持失败。

### B4. 供应商生命周期和安全凭据

对应：BL-PC04-014、015。

1. 每个供应商适配器固定官方端点、默认模型、请求模式和应用内提示版本；用户只输入 API Key。
2. 发布时从供应商官方资料生成生命周期核查记录；若默认模型不可用或进入弃用期，发布必须停止并走显式变更审查。
3. `healthCheck()` 分别报告：端点可达、密钥有效、所选模型对账户可用、请求兼容；不能用通用 `/models` 200 代替模型可用性。
4. 使用合成字符串和受控测试账户完成真实请求 Smoke，验证翻译、取消、超时、限流、无权限、模型不存在、重定向和离线错误。
5. 精确 Windows 安装包使用合成密钥执行：保存 -> 重启 -> 读取 -> 翻译 -> 清除 -> 再次读取失败。
6. 对设置、备份、sidecar、日志、诊断、临时目录、崩溃文件和卸载残留进行密钥扫描；测试失败也必须清除合成凭据。

### B5. 字典、TTS 和简体中文界面

对应：BL-PC04-016、017。

1. 字典验证至少包括真实 MDict+MDD、StarDict/DICT 和 SLOB：选择器导入、重启、划词查询、多词典顺序、异常文件、移除和零网络。
2. TTS 验证实际 Windows 语音枚举以及中、英、日文本播放；覆盖暂停、继续、停止、跳转、语速、语音切换、跨页高亮和关闭回收。
3. 若 CI 无音频设备，使用平台测试接收端证明音频生成；最终候选包仍需一次真实 Windows 设备播放记录。
4. 扫描漫画工作区及其错误、进度、模型、编辑和导出路径的所有用户可见字符串，全部进入 locale。
5. 增加 `zh-CN` 原生 E2E，在最低支持窗口尺寸下验证无截断、无遮挡、键盘可达和主要操作可见。

## 9. 检查点 C：漫画 OCR、编辑和资源闭环

### C1. 生产 OCR 候选选择

对应：BL-PC04-001。

1. 候选评估只采用现有窄适配器，不并入完整外部漫画应用。
2. 建议评估方向：
   - 主路线：可导出为 ONNX 的多语言检测、方向分类和中/英/日识别组合；
   - 后备路线：针对日文漫画识别的独立 ONNX 模型，仅在同一真值集上证明优势后启用；
   - 不在评估完成前把 PaddleOCR、manga-ocr 或任何具体候选宣布为生产依赖。
3. 每个候选固定代码提交、模型文件、模型许可证、训练数据说明、SHA-256、预处理、解码器、语言和 CPU 指令要求。
4. 使用同一合法语料测量检测、识别、竖排、低分辨率、混合语言、灰度和彩色场景，记录字符/词错误率、漏检/误检、耗时和内存。
5. 只有主路线和后备路线均完成许可证、质量、资源和跨平台可行性评审后才能做选择决定。

### C2. 本地运行时、模型包和桌面 OCR 入口

对应：BL-PC04-001。

1. 在既有 `OcrRuntime`/worker 协议后实现按需加载的本地推理适配器；运行时不得在应用启动时加载。
2. 模型包必须包含版本化 manifest、全部 artifact 哈希、许可证、语言、运行时要求、输入输出张量和解码器版本。
3. 导入流程：文件选择 -> 暂存 -> 完整校验 -> 许可证确认 -> 原子安装 -> 可用性验证；失败时删除暂存，不破坏旧版本。
4. 桌面工作区提供 `Run OCR`，支持页、页段和全档选择，并显示模型、语言、CPU fallback、预算和预计磁盘占用。
5. OCR 结果增量写入 sidecar，记录页级状态、模型来源和错误；取消、崩溃和重启后可以恢复或选择性重跑。
6. 模型卸载和移除必须释放会话、文件映射、worker、临时缓存和索引，不影响已有 OCR 文本和人工校订。
7. 精确安装包完成模型导入、校验、选择、中英日/竖排 OCR、取消、恢复、复制文本、移除和卸载矩阵。

### C3. 批处理任务界面

对应：BL-PC04-002。

1. 新增用户可到达的批任务面板，唯一调用既有 `ComicPipelineQueue` 和 `composeComicPipelineStages`，禁止再建立第二套状态机。
2. 支持来源、页/页段、阶段、语言、模型、目标译文、清理方式、排版预设和导出目标选择。
3. 显示文档和页级进度、当前阶段、耗时、错误、重试次数和资源预算。
4. 支持暂停、继续、取消、重试、选择性重跑、版本历史、缓存清理和诊断导出。
5. 检查点必须在每个幂等阶段后原子保存；重启后先核验源文件指纹、模型和设置，再恢复。
6. 队列只能由用户明确创建；翻译阶段到达时才允许调用已选供应商，OCR/清理/排版阶段保持本地。

### C4. 完整漫画编辑器

对应：BL-PC04-003、017。

1. 页面画布支持选中、创建、移动、缩放、旋转、多边形顶点编辑、分割、合并、删除、恢复和阅读顺序拖动。
2. OCR 编辑支持语言、方向、置信度、原文、译文、审批状态和机器/人工修订对比。
3. 掩膜编辑支持画笔、橡皮、恢复、扩张、羽化、区域预览和撤销/重做；所有操作写入可回放 sidecar 命令或修订。
4. 修复支持确定性本地填充和经过批准的可选本地 inpainting worker；失败必须保留原图和掩膜，并允许回退。
5. 排版控制至少包括字体、字号、颜色、描边、对齐、字间距、行距、旋转、方向、竖排 CJK、RTL、溢出和适配。
6. 缺字、字体缺失、文本溢出、过低置信度、无效几何和 worker 失败提供可见诊断。
7. UI 预览与导出使用同一布局模型；为典型页面建立像素/结构视觉回归容差。
8. 撤销/重做、自动保存、崩溃恢复、OCR 重跑和翻译重跑都不能静默覆盖已审批人工修改。

### C5. 流式处理和资源预算

对应：BL-PC04-009、013。

1. 将当前全量 `File`/`Blob`/object URL 会话改为窗口化页面存储：只保留当前页和有限相邻页，其余写入受配额的应用临时目录。
2. PDF 逐页光栅化并立即释放 canvas、ImageBitmap 和对象 URL；压缩包逐项校验并按页暂存。
3. 在读取期间同时限制：条目数、声明和实际解压字节、压缩比、单项字节、尺寸、总解码像素、页数、磁盘配额和处理时间。
4. OCR、清理和排版 worker 使用有界并发；取消信号必须贯穿解码、推理、编码和磁盘写入。
5. 导出先逐页生成内容寻址的临时结果，再按目标格式流式或磁盘汇编；不得同时持有源、RGBA、编码页、转换页和最终归档。
6. 正常、失败、取消和崩溃后都清理只属于当前任务的临时数据；可恢复检查点按明确保留策略处理。
7. 增加压缩炸弹、80MP、数千页、磁盘不足、内存压力、worker 崩溃和取消测试，并记录进程树峰值。

## 10. 检查点 D：精确候选包再验收

### D1. 候选状态冻结

1. 所有 P0/P1 实施合并后冻结范围，不再夹带重构或未来平台功能。
2. 全部源码、依赖锁、子模块、模型 manifest、fixture manifest 和文档处于干净提交。
3. 记录提交、树、子模块、工具链、配置和依赖锁哈希。

### D2. 自动化门禁

仓库脚本名称可在实施时调整，但必须提供等价门禁：

1. pnpm 版本与 `packageManager` 一致；冻结安装成功。
2. TypeScript、Biome、格式、生成输出和生产构建通过。
3. 全量单元测试、核心模块覆盖率和 browser Vitest 通过。
4. production-web Playwright、Tauri integration 和 Windows WebDriverIO 通过。
5. Rust fmt、all-target check、workspace Clippy、单元和集成测试通过。
6. npm production audit、Windows RustSec audit和未来平台警告处置通过。
7. 可执行格式、sidecar 迁移、恶意输入、源哈希和凭据脱敏矩阵通过。
8. 网络白名单、性能预算和临时资源清理通过。
9. 标准 Windows 构建、VersionInfo、安装、升级、启动、关闭、卸载、数据保留和故障注入通过。
10. 签名、SBOM、notices、许可证和子模块证据通过。

建议新增统一只读入口：

```text
pnpm verify:pc-source
pnpm verify:pc-security
pnpm verify:pc-formats
pnpm verify:pc-privacy
pnpm verify:pc-performance
pnpm verify:pc-native
pnpm verify:pc-installer
pnpm verify:pc-release
```

`verify:pc-release` 只编排前述门禁，不复制或改写候选包；任何子门禁失败时返回非零。

### D3. 精确安装包人工/原生矩阵

同一签名候选包必须验证：

- 所有支持格式的导入、阅读、重开、搜索和导航；
- 划词、句段、章节和全书翻译以及取消、限流、超时、重定向和离线失败；
- 四种双语模式在字体、窗口、分页和重开后的锚点一致性；
- 术语表、翻译记忆、校订、导入导出和恢复；
- 真实字典和 Windows TTS；
- OCR 模型包完整生命周期和中英日/竖排日文；
- 漫画区域、掩膜、修复、排版、批处理、重启恢复和 CBZ/PDF/图片集导出；
- 漫画、webtoon、西方漫画、灰度、彩色、低分辨率、混合语言和大页面样本；
- 源文件逐字节不变、sidecar 正确、用户数据按策略保留；
- 关闭后无孤儿进程、端口、临时目录、凭据或模型映射。

### D4. 发布提升

1. 只有全部证据通过后才签名并提升候选字节。
2. 生成内容寻址的验收清单，关联安装包 SHA、签名、提交、CI run、SBOM、notices、格式/性能/隐私报告。
3. 创建版本提交和标签，合入 `main`，推送远端并确认所有必需检查。
4. 确认远端备份后删除已合并过时分支和可重建缓存。
5. 最终工作树必须干净；不得删除源、`.env`、凭据、用户数据、导入内容、sidecar 或不可重建证据。

## 11. 代码精简和资源优化方案

精简必须在功能可达性和证据建立后执行，避免删除当前尚未连接但属于必需范围的服务。

1. 先生成 npm/Cargo/Tauri 命令、capability、插件、worker、public 资源和动态导入的可达性报告。
2. 对 Windows 不需要但未来移动端需要的生物识别、触觉、分享、车载和桥接代码做平台模块拆分，不从仓库直接删除。
3. 审查 sharekit、device-info、deep-link、CLI、WebView upgrade 等继承插件的当前 PC 可达性、权限、包体和未来移植价值。
4. 对 `Annotator.tsx`、library page、`ComicWorkspaceDialog.tsx`、comic workspace service 和 translation workbench 按职责拆分；只有能减少启动代码、隔离状态或提高直接测试性时才实施。
5. 对 Jieba、SimpleCC、PDFJS、字体和 WASM 重复文件建立运行路径测试，确认不存在 worker/离线路径引用后再删除副本。
6. 生产构建显式禁用 Next telemetry，避免构建期非确定网络行为。
7. 未选中的 OCR/inpainting 实验路径只在生产候选确定且迁移、配置和测试完成后删除。

## 13. 风险与处置

| 风险 | 触发条件 | 处置 |
| --- | --- | --- |
| OCR 模型许可证或质量不合格 | 任一 artifact 来源不清或质量/资源未达标 | 不集成；评估下一候选，保持适配器不变 |
| OCR 运行时使包体/内存失控 | 基础启动加载或预算超限 | 改为用户导入、按需动态加载和独立 worker；基础包不携带模型 |
| 漫画全量处理导致 WebView OOM | 多页/大页测试超过预算 | 强制窗口化、磁盘暂存和有界并发，不提高上限掩盖问题 |
| 双语锚点随排版漂移 | 字体/窗口/分页变化后错配 | 使用内容身份和上下文锚点；失配进入人工重关联 |
| 真实 API 测试泄密或产生费用 | Secret 出现在日志或请求失控 | 合成文本、最小请求、Secret masking、限额账户、失败清理 |
| TTS/字典依赖设备环境 | CI 无语音或文件选择能力 | 平台接收端自动化加一次物理 Windows 候选包验证 |
| 签名证书不可用 | 无证书或时间戳失败 | 可构建内部候选，但不得关闭 BL-PC04-019 或发布生产版本 |
| 当前工作树继续膨胀 | R0 未完成即开发 | 停止功能改动，先恢复 Git 写入并固化基线 |
| 为减包删除未来平台代码 | 静态搜索误判动态入口 | 先做可达性、权限和迁移测试；平台拆分优先于删除 |

## 14. 最终通过条件

只有同时满足以下条件，审计状态才能从 `REJECTED` 改为 `ACCEPTED`：

1. BL-PC04-001 至 BL-PC04-020 均有关闭证据；P0/P1 不允许延期。
2. 所有强制自动化、精确安装包和人工/原生矩阵通过。
3. 当前性能预算通过，不存在未处置高危/严重漏洞或可达 unsound 依赖。
4. 生产 OCR、批处理和完整漫画编辑均为用户可到达功能。
5. 隐私捕获证明除显式供应商翻译或回环 Ollama 外无外部流量。
6. 候选包已签名，并绑定干净提交、SBOM、notices、许可证和完整证据。
7. 发布提交和标签已合入远端 `main`，GitHub 必需检查全部成功，工作树干净。
8. 路线图、要求、架构、发布说明和验收状态与实际结果一致。

若任一条件不满足，必须保留 `REJECTED`，不得开始 0.5、不得以模拟测试代替原生功能、不得把计划或服务层存在当作完成。

## 15. 实施记录分离

本方案仍只定义目标、顺序、门禁和风险处置，不承载逐次执行结果。用户授权后的代码、依赖、测试、构建和清理操作，必须以实际命令输出为依据，并记录在整改状态文档；任何未满足的门禁仍保持 `REJECTED`，不得以计划完成、服务层存在或单元测试替代原生功能证据。
